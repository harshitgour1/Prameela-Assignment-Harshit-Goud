# AI Tool Usage

As requested, this document outlines how AI-assisted development tools were used to build this application.

### 1. Which AI tools you used
- **Antigravity** (Google DeepMind's Agentic Coding Assistant)

### 2. Where you used them
- Used across the entire stack (Frontend and Backend) for rapid prototyping, component generation, logic implementation, testing, and Dockerization.

### 3. Why you used them
- **Velocity:** Antigravity was used to scaffold boilerplate (NestJS setup, Prisma schemas, Next.js App Router structure) significantly faster than writing it from scratch.
- **UI Consistency:** Used to correctly implement a fully semantic Tailwind CSS Dark/Light mode using standard design tokens, avoiding manual color-picking.
- **Problem Solving:** Used to rapidly debug tricky UI edge cases, such as Radix/Base UI hydration mismatches, and to optimize the mobile layout into a responsive Card View pattern instead of a horizontal scrolling table.

### 4. Example prompts you provided
- *"Initialize a new Next.js project with Tailwind CSS and shadcn/ui components."*
- *"Create a NestJS backend with Prisma. We need endpoints for creating, listing, searching, and deleting companies."*
- *"Optimize and make the Mobile UI proper and nice. The current table overflows horizontally."*
- *"Check the errors and fix. [browser] A tree hydrated but some attributes of the server rendered HTML didn't match the client properties... fdprocessedid="6ho5tm""*
- *"Add a proper light and dark mode toggle with the proper internal working and Optimized UI."*

### 5. Which generated code you kept
- The vast majority of the NestJS service logic and Prisma queries were generated and kept because they perfectly matched the requirements for searching, paginating, and sorting.
- The Tailwind utility classes for the responsive Card View on mobile were kept entirely, as it implemented the industry standard flawlessly.
- The `docker-compose.yml` and `Dockerfile` configurations were kept as generated.

### 6. Which generated code you modified or rejected
- **Rejected:** Initially, an AI suggestion tried to solve the mobile view by simply hiding table columns using CSS (`hidden sm:table-cell`). I rejected this in favor of a much more robust "Card View" implementation for a true premium mobile experience.
- **Modified:** The AI-generated `Select` component from Shadcn/Base UI was modified because it defaulted to "item-aligned" positioning, which looked awkward. I manually adjusted the configuration to use `position="popper"` with proper alignment.
- **Modified:** The default dark mode colors generated by the AI were a bit harsh. I manually tweaked the `--primary` oklch color variables in `globals.css` to be a softer, subtle brand blue that looked visually stunning in both light and dark modes.
